# SingStudio 雙版本排版重整規劃

日期：2026-10-28；初版 UI 實作：2026-10-31；錄音／字幕與安全區補強：2026-10-31。狀態：手機與桌面排版已套用，錄音播放與來源同步已修補；平台實機驗收仍待完成。

建議方向：Android 採用以歌詞為主的開唱畫面；Windows 採用能同時檢視歌詞、波形與片段的工作區。兩者共用音訊與資料核心，各自安排操作介面。

搭配 [可切換狀態的線框稿](./layout-wireframes.html) 閱讀。線框稿使用示意歌曲與歌詞，不會開啟麥克風、播放或儲存資料，也未連接正式程式。

## 1. 分析範圍與證據限制

- 雙版本指 Android APK / Capacitor 與 Windows EXE / Electron。
- 已讀取 App、來源、歌詞、底部播放器、錄製、片段、作品庫、後製元件，以及相關 CSS 與音訊 hook。
- 已啟動現有 Vite mobile 模式，在瀏覽器以 390 × 844 與 1400 × 900 檢視實際版面。這是共用前端的尺寸預覽，沒有實機錄音、Android 手勢導覽列或 Electron IPC 驗證。
- 手機測量來自未載入歌曲、切至歌詞頁籤、頁面置頂的狀態；不能把此結果當成所有歌曲與所有裝置的精確尺寸。
- 規劃文件與獨立線框稿先於本次實作建立。原始 UI 實作先調整 React UI、操作列 callback 與響應式 CSS；本次依使用者明確要求再擴充音訊引擎、語音辨識設定與 Android 安全區處理。版號、資料結構、廣告與平台識別碼維持。

## 2. 已確認的問題

| 問題 | 現況證據 | 使用時的影響 |
| --- | --- | --- |
| 手機歌詞出現得太晚 | 390 × 844 預覽中，歌詞容器頂端約 y=549；底部固定播放器頂端約 y=759 | 首屏歌詞可見區約 210px，歌唱時還要捲頁 |
| 播放與錄製入口重複 | App 同時放置曲目列快速錄製、LocalPlayerBar、波形播放器、RecordingControls、BottomSystemBar | 同一首歌出現多組播放與錄音控制，辨認成本高 |

| 暫停後的固定錄音按鈕語意不完整 | App.handleToggleRecord 只判斷 isRecording，否則呼叫開始錄音；未判斷 isPaused | 暫停後按固定列「錄音」會走新錄音入口，並非 resumeRecording |
| 歌詞工具佔據演唱空間 | 搜尋、匯入、匯出、偏移校準、對齊常駐歌詞上方 | 低頻設定與正在閱讀的歌詞爭取空間 |

| 手機缺少可達的波形檢視入口 | CSS 在 ≤768px 強制隱藏 timeline-visual-area；目前 BottomSystemBar 沒有波形切換按鈕 | README 所稱的「▲ 波形」入口未出現在目前元件中 |
| 桌面來源與歌詞互相遮換 | leftTab 只能顯示來源或歌詞，來源隱藏時採 offscreen-keep | 調整 YouTube 來源時不能同時檢視完整歌詞 |
| 桌面最小寬度恰逢單欄斷點 | Electron minWidth=1024，CSS ≤1024 改單欄 | 視窗縮到最小時失去雙欄工作區，需額外捲動 |
| 編輯手勢與演唱手勢混用 | LyricsPanel 的歌詞點擊會選取並跳轉；錄製時仍提供時間拖曳 | 演唱中誤觸有改變播放位置的風險 |
| 觸控與閱讀規格偏小 | 底部主要播放鍵 38px，錄音按鈕更緊湊；一般歌詞文字 15px、當句 17.5px | 手持操作及手機架上的閱讀需要重新設計 |

## 3. Android：先準備，再進入開唱畫面

### 畫面與資訊順序

1. **準備歌曲**：本機 / YouTube 來源切換、搜尋或匯入、已選歌曲、歌詞設定、伴奏試聽。底部唯一主按鈕「進入開唱」。作品庫放在此畫面的入口。
2. **開唱**：頂端精簡曲名與返回；中間歌詞舞台；下方錄音狀態、電平與時間；底部固定且唯一的錄製操作區。
3. **試聽與後製**：完成錄音後以全螢幕頁呈現，提供混音試聽、伴奏 / 人聲音量、殘響、進階延遲、命名、儲存與匯出。
4. **作品庫**：獨立畫面，以直式作品卡呈現。演唱畫面不堆疊作品清單。

「準備 → 開唱 → 試聽」是操作階段；不要求每首歌都完成歌詞匯入，無歌詞也能錄製。

### 開唱畫面配置

| 區域 | 提案規格 | 內容 |
| --- | --- | --- |
| 上方列 | 約 52–56px，加上頂端安全區 | 返回、曲名、省略號設定；版本號放準備頁或關於頁 |
| 歌詞舞台 | 本機來源在 390 × 844 目標保留至少 55% 可用高度 | 前一句、當句、接下來兩句；當句 28–34px，可調字級；長句自然換行 |
| 狀態列 | 約 32–40px | 明確「待機 / 錄音中 / 已暫停 / 處理中」文字、時間、輸入電平 |
| 固定操作區 | 約 112–144px，加一次底端安全區 | 待機：試聽、開始錄音；錄音：暫停、完成；暫停：接續、完成 |

高度是實作目標，需依實際安全區、字級與歌曲換行驗收；YouTube 影片顯示時另保留影片區，不強求相同歌詞比例。操作區採版面固定列，中央歌詞獨立捲動，避免靠長頁底部 padding 猜測遮擋高度。使用 100dvh 與 minmax(0, 1fr) 分配可用高度。

### 各狀態的唯一錄音控制

| 狀態 | 主要操作 | 次要操作 | 防止誤觸與回饋 |
| --- | --- | --- | --- |
| 準備中 | 進入開唱 | 試聽伴奏 | 顯示實際來源載入狀態；麥克風未檢查時不可標示已就緒 |
| 開唱待機 | 開始錄音 | 試聽 / 暫停伴奏 | 開始前完成既有廣告與權限流程；成功後才顯示錄音中 |
| 開始處理中 | 不可重複觸發 | 顯示等待狀態 | 廣告倒數、權限等待與開始失敗要能區別 |
| 錄音中 | 暫停錄音 | 完成錄音 | 收起換曲、刪除、校準入口；禁用拖曳跳轉及點歌詞跳轉 |
| 已暫停 | 接續錄音 | 完成錄音 | 直接接續既有錄音；重錄片段另走明確入口 |
| 完成處理中 | 等待音訊片段完成 | 顯示處理狀態 | 收到最後錄音資料後才進入可試聽狀態 |
| 試聽後製 | 播放 / 暫停試聽 | 儲存、匯出、返回調整 | 區分「存作品庫」與「匯出 WAV」的結果 |

### 觸控與細節

- 主要觸控區至少 48 × 48 CSS px；開始錄音視覺主體約 64–72px，暫停及完成具文字標籤，避免只靠顏色。
- 搜尋 / 匯入 / 匯出歌詞與時間校準移到「歌詞設定」抽屜；伴奏音量、耳返與靈敏度放「聲音設定」。原功能保留可達入口。
- 錄音時歌詞點擊不跳轉。暫停後進入明確的「片段編輯」才能定位與重錄；不直接在仍暫停的 MediaRecorder 上任意 seek。
- 無歌詞時顯示曲名、錄製時間與電平，提供返回準備頁加入歌詞的入口，仍可直接開唱。
- 錄音或暫停時的返回操作先提示保留此段或繼續錄製；只有已確認資料可保留，才顯示「已保留」。
- 橫向手機採歌詞與控制並排，維持相同狀態與按鈕語意；低高度時先隱藏次要說明，不縮小必要觸控區。
- 軟鍵盤只在準備與命名階段出現；彈出時輸入框與提交動作必須可見。增加字級時允許長句換行與歌詞區捲動。

### YouTube 來源的特殊安排

- 準備頁保留搜尋與可見播放器。開唱後維持同一個播放器實例與清楚的來源識別，不因頁籤切換重新載入。
- 若仍顯示影片，配置在歌詞上方的獨立區域；不以來源抽屜遮住整個演唱區。
- 先確認現有播放、錄音、暫停、接續能同步，再接到統一操作列。不能只改按鈕文案就宣稱支援同步。
- 不把 YouTube 來源描述成可直接取得本機伴奏音訊；混音與匯出必須反映實際可用音軌。

## 4. Windows：保留工作區，讓演唱與編輯都有位置

建議固定頂端專案列、中央工作區、底端唯一播放 / 錄音列。作品庫以專用檢視或抽屜開啟，不放在工作區下方形成長頁。

### 1400 × 900 的配置目標

- **頂端 56px**：曲名、來源狀態、作品庫入口、v1.0.1。
- **左側 240–280px，可收合**：來源、YouTube 播放器、歌詞設定。搜尋結果只有此區捲動。
- **中央彈性區**：上方歌詞舞台，下方雙軌波形，兩者比例可調；中央寬度至少約 480px。
- **右側 240–280px，可收合**：錄製片段、伴奏 / 人聲音量、耳返與進階設定；長清單獨立捲動。
- **底端約 80–96px**：伴奏試聽、開始 / 暫停 / 接續 / 完成、主時間、輸入電平。錄音狀態與手機一致。

桌面「演唱檢視」放大歌詞並收起側欄；「編輯檢視」放大波形並展開片段。這是相同歌曲與音軌資料的兩種呈現，不建立第二個音訊引擎。

### 視窗縮小規則

- ≥1280px：可展開左右側欄；中央維持足夠寬度。
- 1024–1279px：右側改抽屜，左側可收合，中央維持歌詞 + 波形。不得在 1024px 自動變成整頁單欄。
- <1024px：供平板或瀏覽器使用，採雙區或抽屜，不以作業系統名稱判斷尺寸。
- 桌面最小 1024 × 700 仍需同屏看見主要歌詞、時間與錄音控制；不以加大 Electron 最小視窗尺寸掩蓋問題。
- Space 保留：待機時伴奏播放 / 暫停，錄音時暫停，已暫停時接續，後製時切換試聽；輸入文字與對話框應避開快捷鍵。

## 5. 雙版本維持方式

| 項目 | 已確認現況 | 改版約束 |
| --- | --- | --- |
| JavaScript 套件版本 | package.json = 1.0.1 | 此提案及 UI 實作不自行升版 |
| 前端版本顯示 | Vite 注入 __APP_VERSION__；Electron 可讀 app.getVersion() | 保留版本來源，避免在不同介面硬編碼新版本 |
| Android 版本 | versionName=1.0.1，versionCode=10001 | 排版階段維持；將來若發布渠道要求遞增，再另外確認 |
| Android 身分 | applicationId / Capacitor appId = com.singstudio.app | 保留 appId、簽章與既有資料位置 |
| Windows 身分 | Electron build.appId = com.singstudio.daw | 保留識別碼、現有安裝與可攜版本目標，不與 Android 強制統一 |
| Web 資源路徑 | Vite 輸出 dist；APK 腳本複製到 www，Capacitor webDir=www | 不依 README 的舊目錄描述擅自改路徑 |
| 雙版本產物 | APK / EXE 腳本已有保留另一平台產物的處理 | 不覆蓋舊發行檔；需要建置時先另存現有版本與校驗值 |
| 本機作品 | IndexedDB 與現有型別 | 第一階段不遷移 schema，不清除作品，不換資料庫名稱 |

同時維護 APK 與 EXE，並維持現有版本號，是本提案的預設解讀。若「維持版本」還包含另裝一套舊 UI，需另行確認；這會涉及安裝識別及資料隔離，不能直接更換 appId。

## 6. 實作切分與必須先釐清的相依問題

第一階段以 UI 為範圍：建立手機 / 桌面容器、共用狀態操作列、拆開演唱歌詞與歌詞設定、移動既有片段 / 混音 / 作品庫入口、重整尺寸規則。共用 hooks 與原資料格式維持。既有廣告與贊助流程保留，在真正開始錄音前銜接，不自行刪除或調整商業規則。

建議元件責任：MobilePreparation、MobileSinging、MobileReview；DesktopWorkspace；共用 LyricsStage、RecordingTransport、SourceSettings、AudioSettings、TakesManager 與 Library。由 App 保有同一份歌曲與錄音狀態。切換畫面不銷毀正在使用的 audio / YouTube 實例。

以下是讀取原始碼時發現的相依風險，已更新實作狀態：

1. **YouTube 與錄音同步**：錄音開始、暫停、接續、定位及後製試聽已控制 YouTube 播放器；YouTube 來源 WAV 僅匯出人聲，避免把平台影音誤當成可取得的本機伴奏。
2. **完成時的資料時序**：finishRecording 現在等待 MediaRecorder `onstop` 收到最後一段 Blob 後才切到後製。
3. **多片段保存**：作品庫 schema 仍只保存一段人聲 Blob；現在保存選取片段，沒有選取時保存最新片段，但仍不會保存完整多 Take。這需要另行設計資料結構遷移。
4. **接續電平顯示**：resume 現在會重新啟動輸入電平更新迴圈；Take 長度累計有效錄音時間，不把暫停時間算進去。仍需實機確認。

這些涉及引擎、資料或流程，應與 UI 改版分開列出並取得範圍確認；不能偷偷混入版面調整。若未修正，需明確標示哪些錄製情境尚未通過驗證。

## 8. 實作結果與範圍

- Android 手機版：準備與開唱分開；開唱畫面以歌詞為主、保留底部狀態與錄音控制。YouTube 來源時，播放器排在歌詞上方。作品庫可獨立開啟。
- Windows 桌面版：來源、歌詞與混音 / 片段改成三區工作區；中等寬度改為雙欄與下方混音區。作品庫可獨立開啟。
- 共用前端保留同一份音訊與 YouTube 實例，未因切換畫面卸載來源元件。錄音中鎖定歌詞跳轉與時間軸拖曳；底部控制列提供開始、暫停、接續與完成操作。
- 版本維持 `1.0.1`；Android `versionCode 10001`、`versionName 1.0.1`，Electron `appId com.singstudio.daw`、Capacitor `appId com.singstudio.app` 均未修改。
- 驗收限制：瀏覽器預覽檢查 360 × 640、390 × 844、1024 × 768 與 1400 × 900；未在 Android 實機或 Windows Electron 執行檔驗證。版面需依第 7 節在實機驗收。
- 初版更動集中在 `src/App.tsx`、`src/components/BottomSystemBar.tsx`、`src/components/Header.tsx`、`src/components/LyricsPanel.tsx`、`src/styles/App.css`；後續補強範圍列於第 9 節。

本次開始前工作區已存在 `public/favicon.ico`、`public/favicon.png`、`public/favicon.svg` 的修改與 `docs/` 未追蹤內容，本次未覆寫或回退。`docs/` 內既有線框稿保留。
